# Spec Delta

## Purpose

约束站点头部搜索对 RFC 全文的覆盖范围、结果粒度与成本上限,使"搜索能命中依据原文"成立,
同时不把搜索体验拖垮。

## ADDED Requirements

### Requirement: 头部搜索覆盖两篇 RFC 全文

站点现有的头部搜索 MUST 覆盖两篇 RFC 的全部小节正文与小节标题;既有站内页面(POC 画板、
规则文档页)的可搜索内容 MUST NOT 因此丢失或减少。

#### Scenario: 命中 RFC 原文措辞

- **WHEN** 读者在头部搜索框输入只出现在 RFC 9182 某一节正文中的英文短语
- **THEN** 结果列表出现该节,点击后到达对应小节页并看到那段原文

#### Scenario: 既有内容仍可搜

- **WHEN** 读者输入只出现在规则文档页某条规则说明中的英文短语
- **THEN** 该规则小节仍作为结果出现,行为与加入 RFC 文档区前一致

### Requirement: 结果粒度到小节并可深链

搜索结果的粒度 MUST 到 RFC 小节一级:一节作为一条结果,MUST NOT 把整篇 RFC 压成一条结果,
也 MUST NOT 把同一小节拆成多条互不相关的结果;每条 RFC 结果 MUST 链接到该小节页。

#### Scenario: 一节一条

- **WHEN** 一个查询词同时出现在多篇 RFC 的多个小节中
- **THEN** 每个命中小节各占一条结果,不出现"RFC 8299"这样指向整篇的单条聚合结果

#### Scenario: 区分同名小节

- **WHEN** 结果列表同时包含 RFC 8299 与 RFC 9182 中标题相同的小节(如 Security Considerations)
- **THEN** 每条结果都能读出其所属文档号与小节号,读者不需要点开即可分辨

### Requirement: 结果展示沿用站内既有样式

RFC 结果的展示 MUST 与站内既有结果同一套样式与交互(文档/小节标题加匹配词高亮、上下文片段、
超长片段以省略号截断),本期 MUST NOT 为 RFC 引入独立的结果卡片或新的搜索界面。

#### Scenario: 同一套结果界面

- **WHEN** 一次查询同时命中 RFC 小节与站内自有页面
- **THEN** 两类结果在同一列表中按既有样式呈现,排版、高亮与点击行为一致

### Requirement: 站点搜索成本有上限并可实测

站点 MUST 记录并约束搜索的实测成本:索引载荷体积(未压缩与压缩传输两个口径)、浏览器侧建立
索引耗时、单次查询耗时,以及索引被拉取的时机。本期预算上限为未压缩索引载荷不超过 700 KB、
压缩传输不超过 160 KB、建立索引不超过 250 ms、单次查询不超过 50 ms(以线上实测为准);超出
上限时 MUST 按既定回退路径降低覆盖,而不是无约束增长。

#### Scenario: 上线前实测达标

- **WHEN** 部署后在浏览器中测量搜索索引载荷与建索引耗时
- **THEN** 四项指标均在上述上限内,且测量值记录在变更验收说明中

#### Scenario: 索引拉取时机对读者可解释

- **WHEN** 读者打开站内任意页面(并未使用搜索)
- **THEN** 验收记录说明索引在页面就绪时即被拉取,并给出该次传输的压缩字节数

#### Scenario: 超限触发回退

- **WHEN** 实测超出任一上限
- **THEN** 按回退路径处理(降低 RFC 侧索引覆盖粒度或将其移出默认索引),并重新测量与重新验收结果

### Requirement: 合规外壳不进入索引

搜索索引 MUST NOT 收录站点自撰的合规外壳文本,以免同一段声明在百余条结果中反复命中;RFC
小节正文与标题 MUST 被收录。

#### Scenario: 搜声明用语不刷出百余条

- **WHEN** 读者搜索只出现在合规外壳中的通用措辞
- **THEN** 结果不因每个小节页都带同一外壳而重复刷出该外壳文本
