# Spec Delta

## Purpose

约束站点内 RFC 全文的来源与逐字保真:读者看到的每一段 RFC 文字都能追溯到确定的权威源文件,
且从源到页面的任何一步都不改动一个字节。

## ADDED Requirements

### Requirement: 权威源文件就地留存并可校验

站点 MUST 在仓库内留存 RFC 8299 与 RFC 9182 的纯文本副本,其内容与 rfc-editor 发布的对应
`.txt` 逐字节相等,并随副本记录来源 URL、抓取日期与 SHA-256 校验和。站点运行时 MUST NOT
向 rfc-editor 或任何远程服务发起请求。

#### Scenario: 读者核验副本与权威源一致

- **WHEN** 读者把站点提供的小节页或整篇副本与 rfc-editor 上同一文档的纯文本比对
- **THEN** 两者内容逐字节一致,且页面上可见来源 URL、抓取日期与该副本的校验和

#### Scenario: 站点离线自包含

- **WHEN** 在断网环境打开 RFC 文档区
- **THEN** 全部正文正常渲染,浏览器网络面板除本站静态资源外无任何外部请求

### Requirement: 小节正文必须是原文的连续子串

RFC 正文按原文的编号小节切分为独立页面时,每个小节页承载的正文 MUST 是源文件的一段**连续
字节区间**:不删行、不改空白字符、不删除页眉页脚与分页符、不做任何改写或重排。

#### Scenario: 单节保真

- **WHEN** 取任一小节页面渲染出的正文文本
- **THEN** 该文本在源文件中存在唯一的等字节匹配区间,且未做任何字符级改动

#### Scenario: 拼接等于全文

- **WHEN** 把某篇 RFC 的所有小节正文按其小节顺序依次拼接
- **THEN** 结果与该篇源文件逐字节相等(既无缺口也无重叠),包括小节标题行、点线目录与页码行

### Requirement: 切分不引入未授权修改

系统 MUST 提供可在开发期执行的保真校验,证明上述两条约束成立;校验失败 MUST 以非零退出并
指名出现偏差的小节。站点 MUST NOT 发布任何经过改版、缩写、注释或重排处理的 RFC 正文。

#### Scenario: 有人手工改写了某个小节页

- **WHEN** 某小节正文与源文件对应区间不再逐字节相等
- **THEN** 保真校验以非零退出码报告该小节标识,并给出首个不一致的字节位置

#### Scenario: 切分产生缺口

- **WHEN** 小节区间拼接后短于源文件(有内容未落到任何页面)
- **THEN** 校验报告缺失的字节数与所属小节,并要求重新生成而非手工补齐

### Requirement: 整篇副本可就地获取

站点 MUST 为两篇 RFC 各提供一个整篇下载入口,该入口指向的文件与仓库内留存的源副本逐字节相等。

#### Scenario: 下载整篇

- **WHEN** 读者在小节页或落地页点击"full text"下载入口
- **THEN** 得到与源副本字节相等的文件,且响应内容可直接与落地页标注的校验和比对通过
