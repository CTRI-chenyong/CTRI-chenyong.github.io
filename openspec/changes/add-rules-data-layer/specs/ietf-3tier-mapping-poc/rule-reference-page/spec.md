# Spec Delta

## Purpose

定义映射规则的文档页形态：规则正文以构建期静态 HTML 发布，使站内搜索与深链都能直达单条规则，同时该页呈现的内容必须与画板运行时同源同值，不引入画板没有的结论。

## ADDED Requirements

### Requirement: 规则正文以构建期静态页面发布
系统 SHALL 提供一个站点页面，其规则正文在站点构建期即渲染为 HTML，而不是运行时由脚本注入。站内搜索的语料文件 SHALL 因该页面的存在而包含规则正文，MUST NOT 出现"页面可见但索引为空"的状态。

#### Scenario: 站内搜索命中规则说明
- **WHEN** 访客在站点头部搜索框输入某条规则说明文字中的英文短语
- **THEN** 搜索结果出现该规则所属的小节，点击后落到规则文档页
- **AND** 结果条目携带该小节的锚点

#### Scenario: 不执行脚本也能阅读
- **WHEN** 访客以禁用 JavaScript 的浏览器打开规则文档页
- **THEN** 全部规则的正文仍然完整可见

### Requirement: 每条规则可被深链
规则文档页 SHALL 为每一条规则提供一个小节，小节标题含规则 ID，并 SHALL 提供以该 ID 为片段标识符的锚点，使单条规则可被直接链接。锚点 SHALL 覆盖规则表中的全部条目，ID 与画板使用的编号一致。

#### Scenario: 直接打开某一条规则
- **WHEN** 访客访问规则文档页并带上某条规则的锚点
- **THEN** 浏览器定位到该规则的小节，小节内可见其源路径、目标路径、传播类别、置信标签与 RFC 出处
- **AND** 该小节内容与画板上同名规则一致

#### Scenario: 锚点无遗漏
- **WHEN** 检查规则文档页的锚点集合
- **THEN** 锚点数量等于规则表条目数，且每个规则 ID 恰好出现一次

### Requirement: 文档页与画板同源同值
规则文档页 SHALL 从内核规则数据导出的站点数据文件渲染，MUST NOT 内嵌第二份规则文本。页面上每条规则展示的字段集合 SHALL 与画板规则面板一致：规则 ID、源路径、目标路径、传播类别、置信标签、每条 RFC 出处（文档号 + 章节号 + 章节标题原文 + 源/目标侧标注），以及路径注记与规则说明。DROP 类规则 MUST 显示"无目标路径"，MUST NOT 显示虚构路径。

#### Scenario: 同一条规则两处读数一致
- **WHEN** 访客分别查看画板规则面板与文档页上的同一条规则
- **THEN** 两者的传播类别、置信标签、源与目标路径及 RFC 出处逐字一致

#### Scenario: 说明文本完整呈现
- **WHEN** 一条规则的说明同时含路径注记与推理说明
- **THEN** 文档页两者都展示，不因版面而省略路径注记

### Requirement: 分组与计数与规则表一致
规则文档页 SHALL 按传播类别分组呈现，并 SHALL 显示每组条数与总条数；这些数字 MUST 与规则表实际内容一致，MUST NOT 由页面作者手写常量维护。

#### Scenario: 计数取自数据
- **WHEN** 规则表新增一条 DERIVE 规则并重新导出后构建站点
- **THEN** 文档页的 DERIVE 分组条数与总条数同步增加，无需修改页面文本

### Requirement: 工程推断清单与范围声明可见
规则文档页 SHALL 单独汇总所有标注为工程推断的规则，作为提交工作组讨论的开放问题清单，每条给出推断依据且 MUST NOT 使用"RFC 规定"一类措辞。页面 SHALL 同时给出范围声明：本次覆盖的字段数、所依据模型的叶子声明总数，以及"指标分母是已声明子集而非完整模型"的说明。

#### Scenario: 只看工程推断
- **WHEN** 访客跳到工程推断汇总小节
- **THEN** 小节列出且仅列出置信标签为工程推断的规则，每条附依据说明
- **AND** 标注为标准明确规定的规则不出现在该小节

#### Scenario: 覆盖率不被读成全量结论
- **WHEN** 访客在文档页查看范围声明
- **THEN** 页面同时显示已覆盖字段数与模型叶子声明总数，并说明覆盖率分母的口径

### Requirement: 文档页与画板双向可达
规则文档页 SHALL 提供返回映射画板的链接，画板 SHALL 提供指向该文档页的链接；两处链接 MUST 使用相对路径，MUST NOT 依赖固定的 baseurl 或绝对域名。

#### Scenario: 从画板进入文档页再返回
- **WHEN** 访客在画板规则面板处点击文档链接进入规则页，再点击返回链接
- **THEN** 两次跳转都命中站点自身发布的页面，浏览器网络面板无 404
- **AND** 站点以非根 baseurl 发布时两条链接仍然命中

### Requirement: 页面呈现遵守既有免责与语言约定
规则文档页上凡出现尚未立项的映射 draft 名称处，SHALL 同时显示 `PLACEHOLDER` 徽标与"该名称为占位、尚无对应 IETF 文档"的说明。页面面向 IETF 读者的正文 SHALL 使用规范英文，MUST NOT 出现自造缩写。

#### Scenario: 草稿名带徽标
- **WHEN** 访客查看文档页上标注规则表来源的 draft 名称
- **THEN** 其旁显示 `PLACEHOLDER` 徽标与免责说明

### Requirement: 新增页面不改变站点构建契约
规则文档页 SHALL 作为站点的普通页面参与既有 Jekyll 构建：MUST NOT 新增 Ruby 依赖或 Jekyll 插件，MUST NOT 在主题专有的 `assets/`、`_layouts/`、`_includes/`、`_sass/` 目录下新增或覆写文件，MUST NOT 影响既有页面的渲染与导航。

#### Scenario: 构建结果只增不改
- **WHEN** 站点完成一次 GitHub Pages 构建
- **THEN** 规则文档页与站内搜索语料文件出现在构建产物中，既有页面与导航结构不变
- **AND** 开发工具目录与规划目录仍不出现在构建产物中
