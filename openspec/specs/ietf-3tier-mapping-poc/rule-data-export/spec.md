# ietf-3tier-mapping-poc/rule-data-export Specification

## Purpose
定义 L3SM→L3NM 规则数据的单一真源与导出契约：规则表在仿真内核内人工编辑，站点侧使用的数据文件由开发期脚本导出，二者不一致必须能被机器发现，且导出方向不得让内核反过来依赖站点外壳。

## Requirements

### Requirement: 规则数据只有一个编辑入口
规则表及其配套的字段定义、章节标题表、范围声明、模拟运营商画像、预置输入、结构差异说明与占位草稿信息 SHALL 只在仿真内核的规则文件中人工编辑。站点侧使用的数据文件 SHALL 是它的导出件，MUST NOT 被手工编辑，MUST NOT 成为任何渲染逻辑的独立真源。

#### Scenario: 改规则只改内核
- **WHEN** 维护者新增或修改一条映射规则
- **THEN** 改动落在仿真内核的规则文件，站点侧数据文件由脚本重新导出后随之更新
- **AND** 画板、引擎测试与规则文档页在同一次导出后读到同一份规则内容

#### Scenario: 手工改导出件被发现
- **WHEN** 有人绕过内核、直接编辑站点侧数据文件后运行同步检查
- **THEN** 检查以非零退出码失败，并指出发生差异的数据组或规则 ID
- **AND** 该文件不被接受为可上线状态

### Requirement: 导出内容完整且与运行时一致
导出件 SHALL 覆盖内核规则文件对外暴露的全部数据组，并 SHALL 记录规则所引用的每个 RFC 章节的编号、章节号与该章节标题原文——即与画板运行时看到的引用完全相同，MUST NOT 因导出而丢失 `pathNote`、`note`、置信标签或传播类别中的任何一项。

#### Scenario: 引用标题随行导出
- **WHEN** 导出脚本读取一条带有两条 RFC 出处的规则
- **THEN** 导出件中该规则的每条出处都含文档号、章节号、章节标题原文与源/目标侧标注
- **AND** 标题与内核章节标题表中的字符串逐字相同

#### Scenario: 说明文本不被截断
- **WHEN** 一条 DROP 规则带有解释"为何没有目标路径"的说明与路径注记
- **THEN** 导出件中两个字段完整存在，未缩写、未省略

### Requirement: 导出可重复且逐字节稳定
对同一份内核规则数据连续执行两次导出，SHALL 产出逐字节相同的文件。导出件 MUST NOT 包含时间戳、随机顺序、绝对路径或任何随执行环境变化的内容。

#### Scenario: 重复导出不产生 diff
- **WHEN** 维护者在不修改规则的前提下连续运行两次导出脚本
- **THEN** 第二次运行后版本库中该文件没有变化
- **AND** 同步检查以退出码 0 结束

### Requirement: 漂移检查是开发期工具而非运行时依赖
仓库 SHALL 提供一个开发期一致性检查：它重新从内核规则数据导出并与仓库中的导出件比对，一致时以退出码 0 结束，不一致时以非零退出码失败并输出差异位置。该检查 MUST NOT 成为站点运行时的一部分，MUST NOT 被页面加载。

#### Scenario: 离线执行检查
- **WHEN** 开发机在无网络连接的条件下运行该检查
- **THEN** 检查仅读取仓库内文件并给出通过或失败结论
- **AND** 站点构建产物中不包含该检查脚本

### Requirement: 导出方向不得削弱内核独立性
数据 SHALL 只能从仿真内核流向站点外壳。仿真内核与无主题独立预览页 MUST NOT 读取站点数据目录、MUST NOT 以 `fetch`、`XMLHttpRequest` 或任何网络方式获取规则，MUST NOT 引入以 `/` 开头的绝对资源路径。既有解耦检查 SHALL 在该能力落地后仍然零违规。

#### Scenario: 断网直接打开独立预览页
- **WHEN** 访客从文件系统直接打开无主题预览页并录入客户请求
- **THEN** 映射联动、批次高亮、双向反查与指标读数全部可用
- **AND** 浏览器网络面板中除该目录内的相对资源外没有任何其它请求

#### Scenario: 内核扫描保持零违规
- **WHEN** 运行既有的解耦检查脚本
- **THEN** 内核文件被判定为模板无关，违规计数为 0
