# Lossless mapping from L3SM to L3NM: a browser-local prototype

## 1. Introduction

This repository holds the first iteration of an open prototype that makes the mapping
between the IETF's service and network abstractions visible and checkable: the Layer 3
VPN Service Model (L3SM, RFC 8299) onto the Layer 3 VPN Network Model (L3NM, RFC 9182).
All calculation runs in the browser; the page needs no backend and makes no runtime
network requests. It is published at <https://ctri-chenyong.github.io/net-sim/l3sm-l3nm/>.

## 2. Background

Carrier services are managed through stacked models: what the customer asks for (L3SM),
how the network realises it (L3NM), how a device is configured (device models such as
OpenConfig). That the tiers translate top-down without information loss is an assumption,
not a demonstrated fact: nothing reproduces the translation end to end, and neither
mapping direction has an adopted specification. Maintaining L3SM and L3NM is within the
charter of the IETF ONSEN working group (Operationalizing Network & SErvice abstractioNs).
The prototype takes one step at a time: each mapping rule is made explicit, cites the RFC
text it rests on, and is labelled as specified behaviour or as engineering inference. The
resulting inference list is the output intended for working-group discussion.

## 3. What this iteration provides

* A board holding the L3SM instance and the L3NM instance. One customer input propagates
  as a single batch: affected fields highlight together and carry causal numbers.
* Eighteen rules — COPY (9), DERIVE (5), SPLIT (2), DROP (2). Each states its category,
  its confidence label (thirteen specified, five engineering inference) and the sections
  of RFC 8299 and RFC 9182 behind it. Clicking a rule row focuses the fields it moves;
  clicking a causal number scrolls its rule into view.
* Derived read-only fields (route distinguisher, route targets, provider numbering)
  refuse manual edits and show their generation algorithm.
* Three machine-checked metrics, recomputed live: coverage within the declared subset,
  round-trip difference (L3SM to L3NM and inverted back), and the share of L3NM leaves
  with traceable provenance.
* The same eighteen rules in document form: the rule reference page,
  <https://ctri-chenyong.github.io/net-sim/l3sm-l3nm/rules/>, gives each rule its own
  section and anchor (for example `#R13`), so a single rule can be linked directly and
  the site's search box finds rule prose. The page renders from an export of the board's
  rule table rather than from a second copy of it.
* The full text of the two modelled RFCs, on this site: RFC 8299 and RFC 9182 are copied
  verbatim, one page per numbered section, at
  <https://ctri-chenyong.github.io/rfc/8299/> and
  <https://ctri-chenyong.github.io/rfc/9182/>, reachable by a section-number address and by
  the search box, so a rule's citation leads to the paragraph behind it.
  <https://ctri-chenyong.github.io/rfc/notices/> states the extent and the grant.

## 4. What it does not cover

The device-model tier, the L3NM-to-device mapping, dispatch to real devices, forms
generated by pyang, instance validation by yangson (RFC 7950/7951) and containerised labs
are out of scope. The board covers 12 declared fields while RFC 8299 declares 159 leaf
and leaf-list statements (145 plus 14, counted 2026-10-31), so coverage is a ratio inside
a declared subset, and the page says so wherever it shows one.

## 5. Running it locally

Open `net-sim/l3sm-l3nm/standalone/preview.html` straight from the file system: same
engine, same board, no site theme attached.

## 6. Repository layout

```
net-sim/l3sm-l3nm/index.html   shell page of the board (theme-aware)
net-sim/l3sm-l3nm/app/         rules, engine, board — no theme, no network
net-sim/l3sm-l3nm/rules/       rule reference page, rendered at site build time
net-sim/l3sm-l3nm/theme/       single theme adapter stylesheet

rfc/source/                    verbatim copies of the two RFC texts; never hand-edited
rfc/8299/, rfc/9182/           landing page and one page per section, generated from the copies

tools/                         development-time checks (not published)
openspec/                      change proposals and specs (not published)
```

[`net-sim/README.md`](net-sim/README.md) defines which file may know what about the host
theme, and how to move the prototype to a different template.

## 7. Development-time checks

Run with Node from the repository root; these are not part of the published site, and the
GitHub Actions workflow only builds the Jekyll site.

* `build-rules-data.mjs` — exports the rule table to `_data/ietf-3tier-rules.json`, which
  the rule reference page renders from; `--check` fails when that file no longer matches
  the kernel, so run it after editing a rule.
* `build-rfc-pages.mjs` — cuts the copies in `rfc/source/` at their own numbered headings and
  writes the landing pages, the section pages and the index in `_data/rfc-sources.json`;
  `--check` fails when those no longer match the copies. It reads only the repository.
* `check-decoupling.mjs` — enforces the boundary described in section 6.
* `check-rules-shape.mjs` — every rule and declared field carries the attributes the
  engine and the page require.
* `check-rfc-fidelity.mjs` — proves the published pages are still the source: the recorded
  section ranges cover each copy with no gap and no overlap, and every page decodes back to
  its byte range byte for byte.
* `check-rfc-citations.mjs` — against the RFC copies in `rfc/source/` (no script downloads
  them; the one-time manual fetch is recorded in `rfc/notices/`), checks cited headings and
  titles, that every path node is declared in the matching YANG module, and that nodes
  reported as absent really are.
* `engine.test.mjs` — mapping, inversion and metrics, headless.

## 8. Next iterations

1. L3NM to a device model, with per-device fan-out.
2. A validation page: configuration applied to a real network OS, with dispatch timing,
   running-config difference and connectivity tests.
3. Forms generated by pyang; instance validation by yangson.
4. A one-command lab (containerlab, 3×PE plus 3×CE) so the chain is reproducible on a new
   machine.
